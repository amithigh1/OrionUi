React, Vue & Angular

Orion Admin components are native Custom Elements, so the same single file works in every framework. You don't need separate packages or wrappers to maintain. There is a tiny helper for React and a plugin for Vue.

Install

      npm install orion-admin
      // once, at your app entry point (main.jsx / main.ts):
      import Orion from 'orion-admin';   // defines all <o-*> elements and injects the CSS

Or keep the <script src="…/orion.min.js"> tag in index.html and use the global window.Orion.

React (18 and 19)

Orion.react(React) returns wrapper components. Props become element properties (arrays, objects and functions work in React 18 as well), onXxx handlers subscribe to o-xxx events (for example onRowClick → o-row-click), native events pass through, and ref gives you the element with all its methods.

      import React, { useState, useRef } from 'react';
      import Orion from 'orion-admin';
      const { Select, Datatable, Datepicker, Chart } = Orion.react(React);   // any <o-*> by name

      export function Users() {
        const [role, setRole] = useState('admin');
        const table = useRef(null);
        return (
          <>
            <Select value={role} options={[{ value: 'admin', label: 'Admin' }, { value: 'editor', label: 'Editor' }]}
                    onChange={e => setRole(e.detail.value)} />
            <Datatable ref={table} columns={columns} source={loadUsers} pageSize={25}
                       onRowClick={e => open(e.detail.row)} />
            <button className="o-btn o-btn-primary" onClick={() => Orion.toast.success('Saved')}>Save</button>
            <button className="o-btn" onClick={() => table.current.export('csv')}>Export</button>
          </>
        );
      }
  • CSS-only components need no wrapper: <div className="o-card">. Behaviors work on plain JSX: <input data-o-mask="(999) 999-9999" />.
  • You can also use the raw tags (<o-select>) in React 19. Set complex props and events through a ref.
  • Orion.react(React).wrap('my-element') wraps any custom element.
  • Next.js / SSR: import Orion in a client component ('use client') or with useEffect(() => { import('orion-admin') }, []). Importing on the server is safe but does nothing.

Vue 3

v-model works out of the box on Orion form controls (they expose value and fire native input events). Tell the compiler that o-* tags are custom elements:

      // vite.config.js
      import vue from '@vitejs/plugin-vue';
      export default { plugins: [vue({ template: { compilerOptions: { isCustomElement: tag => tag.startsWith('o-') } } })] };

      // main.js
      import { createApp } from 'vue';
      import Orion from 'orion-admin';
      import App from './App.vue';
      createApp(App).use(Orion.vue).mount('#app');   // adds this.$orion and inject('orion')
    
      <template>
        <o-select v-model="country" :options="countries" searchable />
        <o-datatable :columns="columns" :rows="users" @o-row-click="open($event.detail.row)" />
        <o-daterange v-model="range" />
        <button class="o-btn o-btn-primary" @click="$orion.toast.success('Saved')">Save</button>
      </template>

Use :prop for arrays and objects (Vue sets them as properties). Event names are kebab-case with the o- prefix.

Angular

      // main.ts
      import 'orion-admin';

      // any standalone component (or NgModule)
      import { Component, CUSTOM_ELEMENTS_SCHEMA } from '@angular/core';
      import { FormsModule } from '@angular/forms';

      @Component({
        selector: 'app-users',
        standalone: true,
        imports: [FormsModule],
        schemas: [CUSTOM_ELEMENTS_SCHEMA],
        template: `
          <o-select ngDefaultControl [(ngModel)]="role" [options]="roles"></o-select>
          <o-datatable [columns]="columns" [rows]="users" (o-row-click)="open($event.detail.row)"></o-datatable>
          <button class="o-btn o-btn-primary" (click)="save()">Save</button>`
      })
      export class UsersComponent {
        roles = [{ value: 'admin', label: 'Admin' }, { value: 'editor', label: 'Editor' }];
        role = 'admin';
        save() { (window as any).Orion.toast.success('Saved'); }
      }

ngDefaultControl connects ngModel / formControlName to Orion controls (value property + input event). Property bindings [prop] pass arrays and objects directly, and (o-event) listens to component events.

Svelte, Solid, Lit & plain JavaScript

      <!-- Svelte -->
      <o-select options={roles} value={role} on:o-change={e => role = e.detail.value}></o-select>

      <!-- plain JS -->
      <o-select id="role"></o-select>
      <script>
        const el = document.getElementById('role');
        el.options = [{ value: 'admin', label: 'Admin' }];
        el.addEventListener('o-change', e => console.log(e.detail.value));
      </script>

TypeScript

Types ship in dist/orion.d.ts. They cover the global Orion API and every <o-*> element in HTMLElementTagNameMap, so document.querySelector('o-select') is typed.

Rules of thumb

  • Frameworks may set properties before Orion loads, render children after the element is created, or move elements. Orion handles all of these.
  • Don't mix framework-controlled children with components that manage their own children (for example sortable lists). Use the component's controlled mode or data props.
  • Every event bubbles and is composed, so you can also listen on a parent.
