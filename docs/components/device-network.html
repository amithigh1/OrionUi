Device & Network

Orion.device detects the operating system, browser, engine, form factor and feature support (UA Client Hints with a user-agent fallback), keeps live values for breakpoint, orientation, theme and connectivity, and adds o-* classes to <html>. Orion.network and <o-network-status> report connection quality.

Device information

Static facts are read once; everything that can change (breakpoint, orientation, online, color scheme, pointer, connection) is a live getter. await Orion.device.ready resolves after the asynchronous refinements (UA-CH high-entropy values such as Windows 11 detection, AVIF/WebP decode tests).

Live breakpoint & change events

The breakpoint uses the same media queries as the CSS grid (sm 576 · md 768 · lg 992 · xl 1200 · xxl 1400). Resize the window or rotate a device to see onChange fire.

Feature support

Orion.device.supports has one boolean per capability. webgl is evaluated lazily on first access; webp/avif are confirmed by decoding a tiny image.

Show / hide by device

data-o-show and data-o-hide take a device query. Separate tokens with spaces or commas for any, join with + for all, prefix ! to negate. Elements are re-evaluated on every change.

Classes on <html>

      /* style by device without JavaScript */
      .o-touch .toolbar { gap: 1rem; }              /* bigger touch targets */
      .o-os-ios .app-header { padding-top: env(safe-area-inset-top); }
      .o-offline .sync-button { opacity: .5; }

Parse any user agent

Orion.device.parseUA(ua, { touchPoints, uaData }) is the same parser used internally — handy for analytics or server logs.

Network status indicator

<o-network-status> shows Online, Slow connection or Offline with an icon and text (never color alone). Add toast to pop a toast on changes when Orion.toast is available, and hide-online for an offline-only banner. Changes are always announced to screen readers. Use the buttons to preview states with Orion.network.simulate().

Frameworks & SSR

Everything is SSR-safe: on the server Orion.device reports a desktop with breakpoint 'lg', so render device-specific UI after hydration (or use the CSS classes / data-o-show). Subscribe to onChange in an effect and call the returned function on unmount.
