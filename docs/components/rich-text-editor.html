Rich Text Editor

A zero-dependency WYSIWYG editor: formatting, headings, lists, tables, images, links, code blocks, markdown shortcuts, a slash command menu, mentions and an emoji picker — all built on pure DOM/Range operations (no document.execCommand).

Blog post editor

A larger example: markdown shortcuts (try # , - , 1. , > , ``` , **bold**, *italic*, `code`), the / slash menu, @ mentions, and image upload (mocked with data URLs — swap in upload-image for a real backend).

Formatting toolbar

Bold, italic, underline, strike, inline code, superscript/subscript, headings, text color & highlight, alignment, lists (bullet/numbered/checklist with Tab/Shift+Tab nesting), blockquote, code blocks, tables, images, links, horizontal rule, emoji, clear formatting, source view and fullscreen.

Markdown & HTML output

Standalone Markdown ⇄ HTML — Orion.markdown

The same converter that powers getMarkdown()/setMarkdown() is also exposed directly as a service, for converting Markdown/HTML outside of any editor instance (storing Markdown but rendering HTML elsewhere, importing Markdown files, etc). toHTML() returns unsanitized HTML — run it through Orion.util.sanitize() before inserting it into the page, exactly like the editor does internally.

Character limit & read-only

Form integration

<o-editor> is form-associated: it participates in FormData, native validation (required) and resets with the form.

CSS custom properties

--o-ed-bg — the editor's background. Everything else is driven by design tokens; see .o-prose for the editable typography and .o-tk-* (from the code-editor package) for code-block token colors.

Frameworks

Set the mentions and upload-image properties directly (they are not JSON-attribute friendly since they carry functions) — this works the same in React 19, Vue 3 (ref.value.uploadImage = fn) and Angular. Listen for o-change via a ref, e.g. ref.current.addEventListener('o-change', fn).
