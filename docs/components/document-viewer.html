Document viewer

<o-docviewer> previews whatever a user uploads with one component: PDF (the browser's own viewer), Word documents (converted to HTML by a built-in, dependency-free reader), CSV, JSON, Markdown, source code, images, video and audio — with a toolbar for zoom, download, print and fullscreen. Orion.preview(fileOrUrl, opts) opens the same viewer in a fullscreen dialog, ready for an upload package to call after a file is picked.

Word documents (.docx)

Paragraphs, heading styles, bold/italic/underline/strike, colors, highlights, superscript, hyperlinks, nested bullet & numbered lists, tables with merged cells and shading, and inline images are converted to HTML and rendered in a paper-like page with .o-prose. This is a converter for common Word output, not the full OOXML spec — headers/footers, footnotes, text boxes and SmartArt are out of scope.

PDF

Rendered with the browser's own PDF viewer inside an <iframe> — full fidelity, zero code, but no page-thumbnail rail or text search from us. When navigator.pdfViewerEnabled is false (some mobile browsers), a fallback card offers Download / Open in new tab instead. Building a pdf.js-style renderer is explicitly out of scope for this package.

CSV, JSON & Markdown

CSV renders as a sortable-looking striped table; JSON as a collapsible tree (native <details>, so it needs no extra script); Markdown through a small, safe renderer — escapes everything first, so any raw HTML in the source (even a stray <script> tag, see the bottom of the readme) is shown as inert text, never executed.

Code & plain text

Image, video & audio

Reuses <o-zoom> for images and <o-video> / <o-audio> for playback when the gallery / player packages are loaded (native elements otherwise).

Orion.preview(fileOrUrl, opts)

Opens <o-docviewer> in a fullscreen dialog — the helper an upload package calls after a file is picked or a row's "Preview" action is clicked. Uses Orion.modal when it is loaded in the same bundle, otherwise a minimal dialog on the core overlay stack (as on this page).

Coverage & limitations

  • PDF — delegated entirely to the browser's built-in viewer. No page thumbnails, text search or annotation from this package, and older/locked-down mobile browsers may not support inline PDFs at all (a download card is shown instead).
  • DOCX — covers what most generated or hand-written documents use: paragraph and heading styles, run formatting, bullet/numbered lists (including nesting), tables (column/row spans, shading, alignment) and inline images. Not covered: headers/footers, footnotes/endnotes, comments, text boxes, SmartArt, embedded charts/objects, and tracked changes.
  • Markdown is a small, safe subset (headings, emphasis, links/images, lists with checkboxes, blockquotes, tables, fenced code) — not full CommonMark (no footnotes, definition lists or raw HTML passthrough).
  • Code preview shows line numbers but does not syntax-highlight (kept dependency-free); pair it with your own highlighter via Orion.docx/renderer internals if needed.
