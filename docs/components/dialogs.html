Dialogs

Promise-based replacements for window.alert/confirm/prompt, built on Orion.modal(): a small, centered card with a colored icon badge. Every call returns a promise you can await.

Alert

Orion.alert(text | options) → Promise<void>. Resolves once the user dismisses it.

Confirm

Orion.confirm(text | options) → Promise<boolean>. type sets the icon and color: info, success, warning, danger (or error), question (default). danger also focuses Cancel so Enter is the safe choice.

Type-to-confirm & checkbox

requireText disables the confirm button until the input matches exactly. checkbox adds an extra option and the promise resolves { confirmed, checked } instead of a plain boolean.

Prompt

Orion.prompt(text | options) → Promise<string | null>. Supports validation, a required field, any input type and a multiline textarea (Ctrl/⌘+Enter submits).

data-o-confirm behavior

Intercepts clicks (links, buttons) and form submissions until the user confirms, then continues the original action: the link navigates, the click is re-dispatched (so other handlers and actions run), or the form submits with its original submitter.

API

Orion.alert(text | options) → Promise<void>

OptionTypeDefaultDescription
titlestring—Title. Without a title, text is shown as the title.
textstring—Message (plain text, newlines kept).
htmlstring—Rich message, sanitized with Orion.sanitize.
typeinfo｜success｜warning｜danger｜questioninfoIcon badge and color (error is an alias for danger).
iconstring｜falseper typeCustom icon name, or no icon.
okTextstringOKButton text.

Orion.confirm(text | options) → Promise<boolean | { confirmed, checked }>

OptionTypeDefaultDescription
All Orion.alert options, plus:
confirmText / cancelTextstringConfirm / CancelButton texts.
dangerbooleanfalseRed confirm button, danger icon, and Cancel gets focus (Enter = safe choice).
requireTextstring—Type-to-confirm: the confirm button stays disabled until the input equals this text exactly.
checkboxstring｜true—Adds a checkbox; the promise then resolves { confirmed, checked } instead of a boolean.
checkedbooleanfalseInitial checkbox state.

Default type is question (danger when danger: true). Escape / backdrop click resolve false.

Orion.prompt(text | options) → Promise<string | null>

OptionTypeDefaultDescription
title, textstring—Title and description (a string argument becomes the title).
labelstring—Visible field label (otherwise the title is the accessible name).
value, placeholderstring—Initial value / placeholder.
inputTypestringtextAny <input type> (email, number, password, url…).
multiline, rowsboolean, numberfalse, 4Use a <textarea> (Ctrl/⌘+Enter submits).
requiredbooleanfalseEmpty value shows "This field is required".
validate(value)function—Return an error string (or a Promise of one) to block submission; null/falsy = valid.
okText / cancelTextstringOK / CancelButton texts.
type, iconnoneOptional icon badge, same as alert/confirm.

Resolves the entered string, or null when cancelled. Every returned promise has a .modal property (the underlying Orion.modal handle) so it can be closed programmatically: p.modal.close().

data-o-confirm behavior

AttributeDescription
data-o-confirmMessage (empty → "Are you sure?").
data-o-confirm-titleTitle (the message becomes the description).
data-o-confirm-typequestion, warning, danger (danger styling + safe focus), info, success.
data-o-confirm-textConfirm button text.

Works on links, buttons and forms (<form data-o-confirm="…"> confirms before submitting, using the original submit button).

Keyboard

KeyAction
EnterActivates the focused button (OK / Confirm, or Cancel for danger dialogs); submits the prompt field.
Ctrl/⌘+EnterSubmits a multiline prompt.
EscapeCancel (resolves false / null).
TabCycles focus inside the dialog.

Accessibility & CSS

Alert and confirm dialogs use role="alertdialog"; prompt uses the modal's default role="dialog". Each is labelled by its title and described by its text. Classes: .o-dialog (on the <dialog>), .o-dialog-{alert|confirm|prompt}, .o-dialog-{type}, .o-dialog-layout, .o-dialog-icon, .o-dialog-title, .o-dialog-text, .o-dialog-field, .o-dialog-check. On phones the icon layout centers and the buttons become full width.
