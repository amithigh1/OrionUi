Captcha

<o-captcha type="text|math|slider"> is a self-contained, canvas-drawn challenge, plus <o-recaptcha> / <o-hcaptcha> / <o-turnstile> adapters that lazy-load the real vendor widget.

Client-side captcha is a deterrent, not protection. Every widget on this page runs entirely in the visitor's browser, so a scripted attacker can read the answer (or skip the check) the same way they read this page. It reduces casual spam bots — it does not stop a determined one. Real protection means verifying the result on your server, on every submission: pass a real question/answer through challenge/onVerify below, or check the vendor's token against their siteverify API for the adapters.

<o-captcha> — text, math & slider

All three need no network access. Each demo has its own "Verify" button calling .verify().

Server verification hooks

challenge fetches the question from your backend; onVerify posts the answer back and returns pass/fail — the canvas becomes cosmetic and the real decision happens server-side. Mocked here with an in-page "server".

With Orion.validate

data-o-rules="captcha" runs .verify() as part of a normal form submit.

<o-recaptcha> / <o-hcaptcha> / <o-turnstile>

Shown here without a sitekey, so each renders its placeholder and makes zero network requests. Once you have a real sitekey from Google reCAPTCHA, hCaptcha or Cloudflare Turnstile, just add the attribute — the vendor script then loads lazily and the widget renders for real.
