Camera

<o-camera> is a live webcam capture element with three modes: a plain photo booth, a face-guided selfie mode with auto-capture, and a document mode that delegates to <o-doc-scanner>. Every mode shares the same countdown, mirror, grid, review (retake/use) and permission-state handling.

Basic (photo)

Call start() (or leave auto-start, the default, to call it automatically) to request the camera — a permission prompt is required by every browser. Press the shutter, then Retake or Use photo on the review screen.

Modes

mode="face" overlays an oval guide and auto-captures once a face (via the Shape Detection FaceDetector API where supported, otherwise a brightness/steadiness heuristic) is centered, appropriately sized and held still. mode="document" hides the photo stage entirely and mounts an internal <o-doc-scanner>, whose o-scan event bubbles up through it.

<o-camera mode="photo"></o-camera>      <!-- default -->
<o-camera mode="face"></o-camera>       <!-- oval guide, auto-capture -->
<o-camera mode="document"></o-camera>   <!-- delegates to <o-doc-scanner> -->

Countdown, mirror, grid & aspect

countdown (seconds) announces and displays a large on-screen count before the shutter fires. mirror (default on) flips the front camera's preview and capture horizontally — most people expect to see themselves as in a mirror. grid overlays a rule-of-thirds grid. aspect (e.g. "1/1") crops the captured frame to a fixed ratio regardless of the camera's native ratio.

Device switch, torch & zoom

A device <select> and switch button appear once enumerateDevices() reports 2+ cameras (labels only populate after a permission grant, a browser privacy rule). torch-toggle and zoom-control (both default on) show their buttons only once the active MediaStreamTrack's capabilities report support — most laptop webcams support neither.

No camera at all: the source property

Set source to a MediaStream-like object (a real stream, or a fixture from canvas.captureStream()) or directly to a <video>/<canvas>/ ImageBitmap/ImageData/image URL, and start() pulls frames from it instead of calling getUserMedia — mirror, grid, countdown and capture()/review all behave exactly the same. This demo feeds in a plain <canvas> redrawn every second.

JavaScript API

Orion.camera.capture() opens a modal with a live camera and resolves with the captured File (or null if cancelled) — a one-line way to grab a photo without hand-rolling a dialog.

Orion.camera.capture({ facing, mode, countdown, aspect, format, quality, title, size }) -> Promise<File | null>
Orion.camera.devices() -> Promise<{ deviceId, label }[]>
Orion.camera.supported() -> boolean

Accessibility

The live <video> carries an aria-label and the countdown announces each second via announce(); a successful capture announces "Photo captured". Icon-only buttons (switch camera, torch, retake, use photo) all have aria-labels. Permission/hardware states are shown as readable text with a retry button, not just an icon.

Limitations

  • Camera access requires a secure context (HTTPS or localhost); the insecure state explains this instead of silently failing.
  • Face-mode auto-capture cannot truly confirm "this is a face" without FaceDetector support — the brightness/steadiness fallback just means "a bright, steady, roughly centered frame".
  • torch-toggle/zoom-control and device switching depend entirely on what the active MediaStreamTrack reports; a source fixture reports none of these.
