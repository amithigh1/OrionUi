Query Builder

<o-query-builder> builds nested AND/OR/NOT rule trees with type-aware operators and value editors, then exports them as a parameterized SQL fragment, a MongoDB query object, a human sentence, or a JS predicate you can run against plain arrays. A compact search-bar mode parses a small query language (status:active age>30 "exact phrase" -excluded) into the same tree.

Filtering a live table

Build a query below — every change filters the table instantly via toPredicate(), and the generated SQL / Mongo / sentence update live. Click + Add group to nest an OR group inside the AND root, drag a rule by its grip handle (or focus the grip and press Alt+↑/↓) to reorder it.

Type-aware operators

Each field's type (text, number, date, boolean, select, array) drives which operators and value editor appear — dates and multi-selects use the Orion date picker / select when those packages are loaded, else a native <input>.

Search-bar mode

Click Switch to search bar (or set mode="bar") for a compact, typed alternative that parses into the exact same tree — switch back to builder at any time to see (and keep editing) the parsed rules.

Query language (search-bar mode)

      Orion.qb.parseQueryString('status:active age>30 "exact phrase" -excluded');
      // -> [{field:'status',op:':',value:'active',not:false}, {field:'age',op:'>',value:'30',not:false},
      //     {field:'_text',op:':',value:'exact phrase',not:false}, {field:'_text',op:':',value:'excluded',not:true}]
      Orion.qb.parseToTree(text, fields);          // -> the same Group/Rule tree shape as `value`
      Orion.qb.treeToQueryString(tree, fields);    // best-effort inverse for a flat AND-of-rules tree

key:value, key:"quoted value", key>value, key>=value, key<value, key<=value and key!=value target a field (the operator is resolved from that field's type when fields is passed in); a bare word or "quoted phrase" becomes a free-text contains rule (searched across every declared text-type field, or the whole row if none are declared); a leading - negates any token.

Frameworks

Set fields and value as properties (both accept JSON in attributes too). Listen for o-change to read event.target.value or call any of the export methods.

      <o-query-builder ref={ref} fields={fields} value={value} />
      useEffect(() => { const el = ref.current; const f = e => setValue(el.value); el.addEventListener('o-change', f); return () => el.removeEventListener('o-change', f); }, []);
