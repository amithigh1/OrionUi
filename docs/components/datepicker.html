Date Picker

<o-datepicker> is a typed date input with a popup calendar (a bottom sheet on phones) or an inline calendar: min/max, disabled dates, highlighted dates with dots or badges, week numbers, month & year quick-pick views, several months side by side, multiple dates, a datetime mode and locale-aware names — with the month grid exported as Orion.MonthGrid for your own widgets.

Basic

The value is an ISO date (YYYY-MM-DD); the input shows and parses the locale pattern (Orion.date.localePattern(), e.g. MM/DD/YYYY) and always accepts ISO. Press ↓ in the input to move into the calendar; click the month title to pick a month, then again to pick a year.

Min / max & disabled dates

min / max limit navigation and selection. disabled-dates accepts ISO dates, { "from", "to" } ranges, weekday numbers and the keywords weekends / weekdays — or set a function date => boolean. Disabled days stay focusable but cannot be chosen, and typing one is reported as invalid.

Inline calendar, highlights & week numbers

inline renders the calendar in place (still a form control). highlighted marks dates with a dot (color = a semantic name or any CSS colour), a badge (e.g. a count) and a label (tooltip + screen-reader text). week-numbers adds ISO weeks and week-start overrides the locale's first day.

Multiple dates

mode="multiple" toggles days on and off; the value is an array (one FormData entry per date) and the input lists the dates.

Date & time

time adds scroll-spinner columns (from Time Picker) beside the calendar; the value becomes YYYY-MM-DDTHH:mm. The clock follows the locale (12/24 h) unless hour12 is set; step sets the minute interval.

Formats & typing

format uses Orion.date tokens (YYYY MM M DD D MMM MMMM HH hh h mm A, [literal]). Typed text is parsed with the same format — other separators (. - /) and ISO dates are accepted too; unparsable text marks the field invalid until fixed.

Localization & RTL

Month and weekday names, digits, the input pattern, the first day of the week and 12/24 h clocks come from Intl for the current locale; component strings come from i18n (datepicker.*) or the texts property. Arrow keys mirror in right-to-left layouts.

Forms & validation

Form-associated: name, required, min/max (rangeUnderflow / rangeOverflow), unavailable dates and bad input all feed the browser's constraint validation.

Reusing the month grid

new Orion.MonthGrid(el, options) renders one accessible month (<table role="grid">) and is what the calendar, booking and scheduling widgets build on. Supply isDisabled, dayState (keys become .is-* classes), renderDay for custom cells and onSelect; Orion.MonthGrid.keyTarget(event, date, { rtl }) gives you the standard arrow / Home / End / PageUp / PageDown movement. Orion.Calendar adds captions, month/year views and multi-month keyboard paging on top.

// A 3-month availability overview with the full calendar controller
const cal = new Orion.Calendar(el, {
  months: 3, min: new Date(),
  isDisabled: d => bookedDays.has(Orion.date.toISODate(d)),
  highlight: d => promoDays.has(Orion.date.toISODate(d)) ? { color: 'success', label: 'Promo' } : null,
  onSelect: d => console.log(d),
});
cal.show(new Date(), { focus: true });

ARIA: the input is a combobox with aria-haspopup="dialog"; the popup is a dialog, each month a grid labelled by its caption with gridcells carrying full-date labels, aria-selected, aria-disabled and aria-current="date". Month changes are announced.
