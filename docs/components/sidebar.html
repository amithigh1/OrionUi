Sidebar

.o-sidebar renders a brand, a search filter, sectioned navigation with nested collapsible groups, badges and a footer user card. Active links are detected from the URL automatically. In mini mode, submenus become hover/focus fly-outs positioned with the core place() engine. <o-sidebar-menu> renders the same markup from a JSON tree for single-page apps.

Full sidebar

Mini rail with fly-outs

Add .is-mini (this is what .o-app.is-collapsed does inside a shell) to collapse to icons only. Hover or focus an icon for its label; hover/click a group icon to open a fly-out submenu positioned next to the rail.

Resizable width & dark variant

data-o-sidebar-resizable="200,360" (min,max px) adds a drag handle at the edge — drag it, double-click to reset, or focus it and use the arrow keys / Home / End. .o-theme-dark scopes the sidebar to the dark palette regardless of the page theme (handy for a permanently-dark sidebar in an otherwise light app).

<o-sidebar-menu> (data-driven)

Renders the identical markup from a JSON array — ideal for single-page apps where the menu comes from configuration or an API. current marks the active item by href/id prefix; leave it unset to auto-detect from the URL. This demo fetches the same fixture used by the app-shell dashboard example.

Search filter & active detection

Typing in .o-sidebar-search input fuzzy-filters items and their ancestors, keeping matched groups open and restoring the previous expand state when cleared. A link's href is compared against location to mark it .is-active / aria-current="page" and expand its ancestor groups; opt out per-link with data-o-active="none", or for the whole sidebar with data-o-sidebar="manual".
