Signature

<o-signature> is a form-associated signature pad: smooth pressure/velocity-aware ink on a resize-safe canvas, stroke-level undo, a typed-signature fallback for keyboard-only users, and PNG/JPEG/SVG/points export. value is a trimmed PNG data URL (or null when empty) that participates in native form submission like any other form control.

Basic

Draw with a mouse, stylus or finger. Pen width follows pointer pressure (stylus) or speed (mouse/touch) by default; undo() removes the last stroke, clear() empties the pad.

Typed fallback (keyboard-accessible)

Canvas drawing is inherently pointer-driven. Add typed for a Draw/Type tab pair — the Type tab renders the name in a handwriting-style font as a fully keyboard-operable alternative.

Required, in a form

required blocks submission until signed, using the same native constraint-validation flow as every other Orion form control (:user-invalid styling, reportValidity() on submit).

Export formats

toPNG()/toJPEG()/toBlob()/toFile() for raster output, toSVG() for a vector approximation of the strokes, and toPoints()/fromPoints() to round-trip the raw stroke data (fractions of the pad size, so it survives any resize).

Testing without real pointer hardware

The pad listens for standard pointerdown/pointermove/pointerup events, so a headless test drives it by dispatching real PointerEvents at page coordinates over the canvas. One gotcha: Chrome reports no getCoalescedEvents() for synthetic pointer events, so a test needs to patch that method to return itself first — see src/components/signature/README.md#testing-no-real-pointer-hardware-needed and tests/evals/capture-signature.js.

Limitations

  • Canvas drawing is inherently pointer-driven; use typed when keyboard-only signing must be supported.
  • toSVG() is an approximation (quadratic-curve smoothing through the recorded points), not a pixel-identical vector trace of the canvas ink.
