Barcode

<o-barcode> and Orion.barcode generate eleven 1D symbologies from scratch: Code 128 (auto subset-switching plus forced A/B/C), Code 39, EAN-13, EAN-8, UPC-A, Interleaved 2 of 5 (plus ITF-14) and Codabar. Formats with a check digit (EAN/UPC/ITF-14) compute it for you, or verify a supplied one and throw a descriptive error when it is wrong.

Basic

value and format are the only attributes you usually need. show-text (default on) prints the human-readable value under the bars; EAN/UPC formats extend the guard bars and split the digits either side, matching real retail barcodes.

Every symbology

Set format to any of code128, code128a, code128b, code128c (forced subsets — code128c needs an even number of digits), code39, ean13, ean8, upca, itf, itf14 or codabar.

Checksum validation

Supply just the payload digits (11/12 for UPC-A, 12 for EAN-13, 7 for EAN-8, 13 for ITF-14) and the check digit is computed for you. Supply the full length including a check digit and it is verified — a wrong one throws instead of silently drawing a bad code. Try editing the value below.

Change the last digit of 4006381333931 and the element shows "invalid EAN-13 check digit (expected 1, got …)" instead of a barcode — the same error Orion.barcode.encode() throws.

Styling

height, module-width, margin, font-size, color/background and guard-bars (EAN/UPC only) control the rendering; download adds a PNG export button, matching <o-qrcode>.

Generate → scan round trip

Every symbology above can be read back by <o-scanner>'s pure-JS decoder without a camera. This renders the code to an offscreen canvas and decodes it on click.

Accessibility

The rendered <svg> has role="img" and an aria-label combining the format and value, so screen readers announce e.g. "ean13 4006381333931" even with show-text off. The download button is a standard, keyboard-operable <button>.

Limitations

  • Code 128's automatic planner switches to subset C for runs of 4+ digits and otherwise stays in A/B; it does not search for the globally shortest encoding the way some libraries do (rarely matters — output is always a few bytes, not a scanability issue).
  • Only ASCII 0–127 is supported in Code 128 (A/B); Code 39 supports 0-9 A-Z space - . $ / + % only (lowercase is upper-cased automatically).
  • GS1 Application Identifiers (parentheses/FNC1-delimited GS1-128 payloads) are not specially parsed — pass the raw digit/character string you want encoded.
