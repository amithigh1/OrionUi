Email Preview

<o-email-preview> renders an HTML email body inside a sandboxed iframe — the sandbox never includes allow-scripts, so nothing in the message can ever run, no matter what it contains. It ships a device-width toolbar, a dark-mode simulation, images on/off, zoom, a plain-text view, a syntax-highlighted source view and a one-line inbox-row view.

Overview

Give it an html string (and optionally subject, from, to, preheader). The body is sanitized (scripts, event handlers and unsafe URLs are stripped; <style> is kept since email HTML relies on it) and set as the iframe's srcdoc — never as src with a blob/data URL, which can inherit privileges in some browsers.

Use the toolbar to switch Preview / Text / Source / Inbox row, resize to Desktop / Tablet / Mobile, toggle Dark mode simulation and Images, and change Zoom.

Dark-mode simulation

The Dark toggle simulates a mail client that forces its own dark palette onto a message with no dark styles of its own — an approximation, not a pixel-accurate reproduction (see the README for the documented limits: a colored CTA button gets muddled here exactly like it would in a real forced-dark inbox). If the email already declares <meta name="color-scheme" content="light dark"> or a prefers-color-scheme: dark rule, this component leaves its styling alone instead of double-darkening it.

Text-only & highlighted source

The Text view is a small dependency-free HTML→text pass (block elements become line breaks, links become label (url), images become [alt text]). The Source view is the raw HTML, syntax highlighted with Orion.highlight(html, 'html') — the same highlighter used by <o-code-editor> — with a plain escaped fallback when that component isn't part of the bundle.

Inbox-row view

view="inbox" is not a separate custom element — it swaps the same component's toolbar/meta for a single truncating row (sender initial, bold sender, subject and preheader). Set toolbar="false" to stack several as a plain list, like a real inbox.

Send test

The Send test toolbar button (or el.sendTest()) asks for an address — Orion.prompt() when the dialogs component is loaded, otherwise a small built-in popover — and emits o-send-test with { to }. Wire that up to your real test-send API.

Programmatic modal

Orion.emailPreview(html, options) opens the same viewer in a small focus-trapped modal, built directly on the core overlay stack (no dependency on Orion.modal). Returns a handle with close() and a closed promise.

Keyboard

  • Esc closes the modal.
  • Tab / Shift+Tab cycle through the toolbar, panel controls and close button without leaving the dialog (focus trap).
  • Every toolbar control is a native <button>, so Enter / Space activates it and normal Tab order reaches all of them.

CSS variables

--o-ep-w-desktop (640px), --o-ep-w-tablet (480px), --o-ep-w-mobile (375px) control the preview frame's width per device preset.

Orion.emailPreview(html, options?)

See the programmatic modal demo above. Returns { el, viewer, close(reason?), closed }; options accepts every prop above plus title, trigger and onClose(reason).
