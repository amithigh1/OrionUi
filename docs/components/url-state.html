URL State & Deep Linking

Orion.url keeps UI state (filters, pagination, sort, selected tab) in the address bar with types and history, so reloads, the Back button and shared links restore the exact view. Orion.deeplink turns links such as #invite or ?open=user:42 into actions that open tabs, dialogs and items.

Read & write

set() pushes a history entry (pass { replace: true } to replace it) and batches every call made in the same tick into one entry. null, '' and empty arrays remove the key. Values are typed on the way in and out.

Filters bound to the URL

Two-way bindings keep controls and the URL in sync: typing updates the URL (debounced), Back/Forward and shared links update the controls. Values equal to the default are removed for clean URLs. data-o-url="key" binds a form control declaratively; Orion.url.bind(key, { get, set, type }) binds anything (here the page number and the sort order).

Deep links

Register handlers by name, or mark elements with data-o-deeplink. On load, hashchange and Back/Forward, links like #tab=billing, #invite or ?open=user:3 run their handler: triggers are clicked (so data-o-toggle semantics apply), <dialog>/<details>/elements with an open() method are opened, anything else is scrolled into view and highlighted. data-o-deeplink-sync writes the link when the user opens it and removes it on close.

      // open an order drawer from  /orders#order=1042  or  /orders?open=order:1042
      Orion.deeplink.register('order', id => drawer.open(id));
      const href = Orion.deeplink.link('order', 1042);        // "https://app.example.com/orders#order=1042"
      Orion.deeplink.link({ tab: 'billing', user: 42 }, { query: true });   // "…?open=tab:billing,user:42"
      Orion.deeplink.copy('order', 1042);                     // copy to the clipboard

AttributeDescription

Frameworks & routers

Orion.url writes with history.pushState/replaceState, preserving history.state so React Router, Vue Router and Angular Router keep working. If your router navigates by itself, call Orion.url.sync() afterwards (automatic in browsers with the Navigation API). On the server, get() returns fallbacks and set() is a no-op.
