Workflow Designer

<o-workflow> extends <o-diagram> with a typed node palette (Start, Task, Approval, Condition, Parallel split/join, Delay, Email, Webhook, Script, End), a schema-driven configuration panel per node type, structural validation with error badges, a vertical auto layout, and a token "simulate" mode. Everything <o-diagram> can do — pan/zoom, undo/redo, export, keyboard control — works the same way here.

Approval workflow

Drag a node type from the palette onto the canvas, connect ports the same way as <o-diagram>, and select a node to edit its fields in the properties panel. This is a complete, valid leave-request approval flow.

Node types & ports

Every built-in type has fixed named ports (used for routing and for fromPort/toPort on edges) instead of the four generic sides a plain <o-diagram> shape uses. wf-condition and wf-split each expose two labelled outputs; wf-join exposes two labelled inputs.

Dropping a node from the palette or calling addNode({ type: 'wf-condition', ... }) fills in its named ports automatically (Orion.workflow.ports) unless the node already specifies its own ports. Field values live under node.data and round-trip through getNode(id).data / updateNode(id, patch) like any other diagram node data.

Structural validation

validate() runs automatically after load and after every committed change, and fires o-validate. It flags, per node: more than one Start node, an End unreachable from Start, and any port with nothing wired to it (both inputs and outputs — a Condition's unused "No" branch is flagged just like a task with no outgoing edge). A node with problems gets a small warning badge; select it to see the messages listed above its fields in the properties panel.

A cycle back into the flow does not on its own fail validation (only unreachable-End, multi-Start and dangling ports do) — <o-workflow> is a diagram, not an execution engine, so a loop is valid structure; simulate() below will just keep circling until you stop it.

Simulate

simulate() samples one path from Start to End (first untried outgoing edge at each fork) and animates a token along it, highlighting the active edge; stopSimulate() stops it (also called automatically on disconnect). The toolbar's play/stop button calls toggleSimulate().

Keyboard & accessibility

<o-workflow> inherits every keyboard shortcut and accessibility behaviour of <o-diagram> unchanged (Tab between nodes, arrows to nudge, Enter/F2 to edit a label, Delete, Ctrl/⌘+Z/Y, Shift+F10 for the action menu, +/−/0/1 to zoom). Simulate has no dedicated shortcut; toggle it from the toolbar button or call toggleSimulate().

CSS variables

All of <o-diagram>'s --o-dg-* variables apply (node cards are drawn on top of the same canvas). Node card tone colors come from the semantic tokens (--o-primary, --o-success, --o-warning, --o-info, --o-danger, --o-secondary, --o-dark) per type, not a separate --o-wf-* palette.
