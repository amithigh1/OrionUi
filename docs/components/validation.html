Validation

Orion.validate(form, options) is the validation engine behind every Orion form: a rule-string mini-language (data-o-rules="required|email|min:3"), live/blur/async checks (including remote uniqueness checks), an accessible error summary, focus management and Orion.serialize(). It works on plain HTML forms — no other package required.

Basic usage

Add data-o-validate to a <form> and data-o-rules to each field. See Form controls for the input styling itself.

Realistic example: registration form

Combines a mocked remote availability check (remote:checkEmailTaken), password confirmation (same:), and a required checkbox (accepted). Try taken@example.com to see the remote rule fail.

Rule reference in action

Every field below fires on blur (data-o-live="blur" is the default) so you can see each rule's message. See the full token list in the API section.

Error summary & focus management

Set summary: true (or data-o-summary) to render an .o-validation-summary alert that links to every invalid field. On submit, the first invalid field is focused and scrolled into view automatically.

Custom rules

Orion.validate.rule(name, fn, message) registers a reusable rule. This one requires an even number.

Orion.serialize(form)

Nested names, checkbox groups and multi-selects all become a plain nested object.

Orion.fill(form, data) & Orion.formFields(form)

Orion.fill() is the inverse of Orion.serialize(): it sets control values from a (possibly nested) data object, using the same user[address][city] / tags[] name convention, and dispatches input/change on every control it changes (so data-o-validate and anything else listening reacts normally). Orion.formFields(form) returns the named controls in DOM order — native inputs and any Orion form-associated custom element — which is what serialize()/fill() iterate over internally, and is handy on its own for building a review step or a "which fields are on this form" inspector.

Custom messages & i18n

Override a built-in message per field with data-o-messages='{"rule":"text"}', or globally by adding to the validation i18n namespace with Orion.i18n.add(locale, { validation: { required: '…' } }).

Keyboard & accessibility

Fields are validated on blur by default so keyboard users aren't interrupted mid-typing. On a failed submit, the first invalid field is focused and scrolled into view, and the error count is announced to screen readers (announce()) even without a visible summary. Every invalid control gets aria-invalid="true" and an aria-describedby pointing at its error text (merged with any help text). The summary's links jump focus straight to each field.
