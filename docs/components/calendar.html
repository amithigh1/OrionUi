Calendar

<o-calendar> is a full scheduling calendar: month, week, day, list and year views, click-and-drag event creation, drag-move and drag-resize, recurring events (RFC 5545 RRULE), business hours, week numbers and locale-aware formatting. Events come from a plain array, an async range function or a URL. See Recurring events for RRULE details and Scheduler for the resource timeline views.

Team calendar

A daily standup (weekdays), a public holiday, a multi-day conference and a few one-off meetings. Switch views with the toolbar or press M W D A Y. The calendar is editable and selectable: drag on an empty slot to create an event, drag an event to move it, drag its edges to resize it, and click an event to see its details.

Event sources

Set events (an array — shown above), an async source(rangeInfo) function that returns events for the visible range (results are cached per month), or a URL string that receives ?start=&end= query parameters and returns JSON. All three can be mixed: events is for events you own locally, source for anything fetched.

Drag-and-drop scheduling

Drag an unscheduled item from the list onto the calendar (data-o-calendar-draggable), then drag the created event to another day or resize it. o-event-change is cancelable — call event.preventDefault() (or return false) and the change is reverted, or call detail.revert() later (for example after an API call fails).

Business hours & week numbers

business-hours shades hours outside { days, start, end } (or an array of ranges) in the week/day and resource views. week-numbers adds an ISO week column to month and time-grid views. first-hour / last-hour crop the visible day, scroll-time sets the initial scroll position and slot-minutes the grid granularity.

Locale, week start & 12/24-hour clock

Month names, weekday labels, the first day of the week and the 12/24-hour clock all come from Orion.date / Orion.i18n — switch the site language (top bar) and the calendar re-renders. Override per instance with locale, week-start (0 = Sunday) or hour12.

Custom event content & API access

eventContent(event, info) replaces a chip's default markup (return an element, a Orion.util.html template or a string). eventDidMount({ el, event, view }) runs after an event chip is inserted, for tooltips or third-party widgets. Buttons below drive the imperative API.

Programmatic factory — Orion.calendar()

Orion.calendar(target, config) creates (or configures an existing) <o-calendar> inside target and assigns every key of config as a property. Note the naming: the element is <o-calendar> and its class is registered as Orion.FullCalendar — Orion.Calendar is a different class (the datepicker package's month-grid widget). Use the Orion.calendar() factory or the tag directly; you rarely need the class itself.

      const cal = Orion.calendar('#host', { view: 'month', events: [...] });
      // Equivalent to: const cal = document.createElement('o-calendar'); Object.assign(cal, config); host.append(cal);
