Realtime

Resilient WebSocket, ASP.NET Core SignalR and Server-Sent Events clients with reconnect backoff, heartbeats, offline awareness and send queues, plus polling and live DOM refresh. <o-live-indicator> shows the connection status. There are no dependencies. Even the SignalR hub protocol is implemented from scratch.

Overview

Every client is an event emitter with a status of connecting | open | reconnecting | closed and registers itself in Orion.realtime.clients, which is how <o-live-indicator for="id"> finds it. Reconnects use exponential backoff with jitter. They pause while the browser is offline and resume immediately when it comes back. The demos talk to in-browser mock servers, so they need no network. Pass a real wss:// or hub URL in your app.

Clients are constructors you can inject for tests ({ WebSocket, EventSource, fetch } options) and they load safely in Node for SSR. Nothing connects until you create a client.

WebSocket

JSON is on by default. Objects are encoded, incoming strings are parsed, and messages shaped like { type: 'price' } also fire a 'price' event. send() queues while the socket is connecting or reconnecting and flushes in order once it opens. The heartbeat sends a ping every interval and drops the socket when nothing arrives within timeout, which catches dead connections that never fire close.

      const ws = Orion.ws('wss://api.example.com/live', {
        id: 'live',                                              // for <o-live-indicator for="live">
        protocols: ['v1'],
        reconnect: { min: 500, max: 30000, factor: 2, jitter: 0.5, maxRetries: Infinity, shouldReconnect: ev => ev.code !== 4401 },
        heartbeat: { interval: 25000, timeout: 10000, message: { type: 'ping' } },
        queue: true,                                             // send() while connecting / offline
      });
      ws.url = () => `wss://api.example.com/live?token=${auth.token}`;   // a function gives each attempt a fresh token
      ws.on('order.created', msg => table.refresh());

SignalR

Orion.signalr(hubUrl, options) speaks the ASP.NET Core SignalR JSON hub protocol over WebSockets. It covers negotiation (including Azure SignalR redirects and access tokens), the handshake, record-separator framing, invocations with completions, streams, client results, keep-alive pings every 15 s, a 30 s server timeout and automatic reconnect. The API follows @microsoft/signalr, so existing code ports easily.

      const hub = Orion.signalr('https://api.example.com/hubs/orders', {
        accessTokenFactory: () => auth.token,        // Authorization header for negotiate, ?access_token= for the socket
        reconnect: [0, 2000, 10000, 30000],             // or { nextRetryDelayInMilliseconds: ctx => ms | null } or false
        headers: { 'X-Tenant': 'acme' }, skipNegotiation: false, keepAliveInterval: 15000, serverTimeout: 30000,
      });
      hub.on('OrderCreated', order => grid.add(order));
      hub.on('GetClientTime', () => Date.now());        // client results: the return value is sent back to the server
      await hub.start();
      const total = await hub.invoke('GetTotal', { month: 9 });
      for await (const tick of hub.stream('Ticker', 'ORN')) chart.push(tick);

Server-Sent Events

Orion.sse(url, options) wraps EventSource. It parses JSON, fires one event per SSE event: type (on() subscribes lazily), and reconnects with backoff. It also keeps working after HTTP errors, where the native EventSource gives up. On reconnect the last event id is sent as ?lastEventId=… so the server can resume.

Live data refresh

Orion.poll(fn, options) runs fn({ signal, count }) on an interval. Runs never overlap. Polling pauses while the tab is hidden or offline and catches up when it returns, and errors back off exponentially up to maxInterval. Orion.live(el, { url | source, render }) keeps a DOM region fresh. It fetches a URL on an interval or subscribes to a push source (Orion.ws, Orion.sse, Orion.signalr or any emitter). HTML strings are sanitized, while output from your own render() is trusted.

      // push: re-render a region whenever the socket sends { type: 'stats' }
      Orion.live('#stats', { source: ws, event: 'stats', render: (s, el) => Orion.util.html`<b>${s.total}</b> orders` });
      // pull: HTML fragment every 30 s (sanitized)
      const kpis = Orion.live('#kpis', { url: '/fragments/kpis.html', interval: 30000 });
      kpis.refresh(); kpis.stop(); kpis.destroy();

Live indicator

<o-live-indicator> shows a status dot and a label. Status is also carried by shape: a pulsing ring means connected, a blinking dot means (re)connecting, and a hollow dot means disconnected or offline. for="auto" (the default) combines every client. for="id" follows one client, and setting the client property binds any object that has a status. Add pill for a chip or compact for a dot only, which keeps the label for screen readers and in the tooltip.

Testing without a server

Mock servers run in the page. Clients connect to them automatically when the URL matches, or you can pass the mock constructors explicitly. Use drop() to simulate a network loss (abnormal close 1006) and refuse(true) to simulate a server that is down.

      const srv = Orion.realtime.mockServer('wss://demo.local/ws', (socket, { url, query }) => {
        socket.send({ type: 'hello' });
        socket.on('message', data => socket.send(data));       // echo
      }, { latency: 20 });
      srv.broadcast({ type: 'news' }); srv.drop(); srv.refuse(true); srv.close();
      Orion.ws('wss://anything', { WebSocket: Orion.realtime.MockWebSocket });   // explicit injection

      const hub = Orion.signalr.mockHub('/hubs/chat', {
        methods: { Add: (a, b) => a + b, *Counter(n) { for (let i = 0; i < n; i++) yield i; } },
        onConnected(id) { this.clients.caller.send('Welcome', id); },
      });
      hub.clients.all.send('ReceiveMessage', 'bot', 'hi'); hub.drop(); hub.sendClose('maintenance', true); hub.close();

      const feed = Orion.sse.mock('/api/stream', conn => conn.send({ n: 1 }, { event: 'tick', id: '1' }));

For end-to-end tests against a real server, docs/examples/services-a-tests-rt.html runs the same suites against a Node WebSocket, SignalR and SSE server.
