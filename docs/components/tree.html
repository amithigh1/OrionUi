Tree

<o-tree> renders a hierarchical list — file explorers, permission trees, org charts, category pickers — with lazy loading, tri-state checkboxes, drag-and-drop reordering, search with highlighting, and virtual scrolling for tens of thousands of nodes. Every row is a real role="treeitem" with full WAI-ARIA keyboard support.

Overview

Give the tree a nodes array of plain objects, or write nested <ul><li> markup and let it parse that once on connect.

      const tr = document.querySelector('o-tree');
      tr.nodes = [
        { id: 'src', label: 'src', expanded: true, children: [
          { id: 'app', label: 'app.js' },
          { id: 'lib', label: 'lib', children: [{ id: 'util', label: 'util.js' }] },
        ] },
      ];
      tr.addEventListener('o-select', e => console.log(e.detail.node));
      tr.addEventListener('o-toggle', e => console.log(e.detail.node.label, e.detail.expanded));

File explorer with lazy folders

Set filetype for automatic folder/file icons (by extension), and mark a node lazy: true to fetch its children the first time it expands via the load(node) option — the row shows a spinner, and a failed load shows a retry affordance. Drag files and folders to reorder or re-parent them (draggable); drop near the top/bottom third of a row to reorder, or the middle to move inside a folder.

Double-click a name (or press F2) to rename it. Right-click (or Shift+F10) fires o-context — wire it to your own menu (dropdown/menu is a separate package).

Permissions tree (tri-state checkboxes)

With checkboxes, checking a group checks every descendant; checking some-but-not-all descendants shows the native indeterminate state on every ancestor. getChecked() returns the fully-checked nodes (a partially-checked group is not included).

Search & highlight

filterable shows a built-in search box (or call filter(query) yourself). Matches are highlighted and every ancestor of a match is shown, temporarily expanded, without disturbing the tree's real expand state — clear the search and it's exactly as you left it.

Drag & drop with validation

canDrop(dragNode, targetNode, position) vetoes a drop before it happens — here files cannot be dropped directly onto the board's root level, and a category cannot be dropped inside another category.

Virtual scrolling — 10,000 nodes

Only the rows near the viewport are ever in the DOM (virtual="auto" switches on above 300 visible rows; force it with virtual="on" / "off"). Expanding the root below flattens 10,000 leaves into the visible list instantly.

Programmatic factory — Orion.tree()

Orion.tree(target, options) builds an <o-tree> from target (a selector or element — if it isn't already an <o-tree>, it is replaced by one, not appended inside) and assigns options as properties, returning the element. The tree's row list is a scroll viewport, so give the returned element an explicit height.

      const tr = Orion.tree('#host', { nodes: [...], checkboxes: true });
      // If #host isn't already an <o-tree>, it is REPLACED by a new one — style/size the returned element (needs an explicit height).

API

Props / attributes

PropTypeDescription
nodesArray{ id, label, icon, children, expanded, checked, disabled, lazy, badge, data }, recursive.
selectionString'none' | 'single' (default) | 'multiple'.
checkboxesBooleanTri-state checkboxes with automatic parent/child cascade.
filetypeBooleanAutomatic folder/open-folder/file-by-extension icons when a node has no explicit icon.
filterableBooleanShows a built-in search box (or call filter(query) yourself).
draggableBooleanEnables drag & drop move/reorder.
canDropFunction(dragNode, targetNode, position: 'before'|'after'|'inside') => boolean.
loadFunctionasync (node) => children[] — called once the first time a lazy: true node expands.
renderLabelFunction(node, tree) => string | SafeHTML | Node — replaces just the label cell.
rowHeightNumberPixel row height used for layout and virtualization math (default 28).
virtualString'auto' (default, on above 300 visible rows) | 'on' | 'off'.
readonlyBooleanNo rename, drag, or checkbox changes; browsing and o-select/o-toggle still work.
texts / labelObject / StringPer-instance text overrides / aria-label of the tree region.

Methods

MethodDescription
expandAll(id?) / collapseAll(id?)Expand/collapse everything, or just one node's subtree.
expandTo(id)Expand every ancestor of a node and scroll to it.
getNode(id)The raw node object (or null).
addNode(parentId, node, index?)Insert a node (root when parentId is null).
updateNode(id, patch)Merge fields into a node.
removeNode(id)Remove a node (and its subtree).
getChecked() / getSelected()Fully-checked nodes / currently selected nodes.
select(id, opts?) / toggle(id, expanded?) / check(id, checked?) / rename(id)Programmatic equivalents of the user interactions.
filter(query) / clearFilter()Apply / clear the search (returns the match count).
scrollTo(id)Expand ancestors and scroll the node into view.
setNodes(nodes)Replace the whole tree (same as tr.nodes = nodes).

Events

EventDetail
o-select{ node, id, ctrlKey, shiftKey }.
o-toggle (cancelable){ node, expanded }.
o-check{ node, checked } — fired once for the node the user (or check()) toggled; cascade updates are silent.
o-move (cancelable){ node, target, position } — a drag (or nothing else yet) moved a node.
o-rename (cancelable){ node, value, previous }.
o-context (cancelable){ node, x, y } — hook your own context menu (right-click, long-press or Shift+F10).
o-filter{ query, count }.

CSS

Custom properties: --o-tree-indent (default 1.25rem), --o-tree-row-h. Structural classes: .o-tree-scroll, .o-tree-row (.is-selected, .is-disabled, .is-current), .o-tree-toggle (.is-expanded, .is-leaf), drop indicators .drop-before / .drop-after / .drop-inside / .is-drop-denied.
