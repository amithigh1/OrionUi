Speech

Orion.speech wraps the Web Speech API: listen() for speech-to-text and speak() for text-to-speech, plus a data-o-voice dictation behavior and an <o-tts> read-aloud element with word-by-word highlighting. Both engines are optional browser APIs — every entry point has a graceful "unsupported" state, and both can be swapped for a fake implementation so this whole page (and its tests) work with no microphone or audio output.

data-o-voice dictation

Adds a mic button to a text field. If your browser supports SpeechRecognition, click it and speak — interim words show greyed in a small bubble and commit at the caret when final.

<o-tts> — read aloud with highlight-as-spoken

Reads its text via Orion.speech.speak(); the word currently being spoken is highlighted from the utterance's onboundary events. If your browser has no voices installed, Play will still run through start/end with no highlight.

Testing with no microphone or audio output: fake engines

Orion.speech.recognition.use(fakeCtor) and Orion.speech.synthesis.use(fakeSynth) swap in a fake implementation — this is exactly what tests/evals/capture-speech.js uses, and it's wired up live on this page so the demos below work identically with no browser speech support and no hardware at all.

JavaScript API

Orion.speech.listen({ lang, interim, continuous, onResult, onStart, onEnd }) -> { stop(), abort() }
Orion.speech.speak(text, { lang, voice, rate, pitch, volume, onBoundary, onStart, onEnd, onError }) -> { cancel(), pause(), resume(), utterance }
Orion.speech.voices() -> SpeechSynthesisVoice[]
Orion.speech.voicesReady() -> Promise<SpeechSynthesisVoice[]>
Orion.speech.supported / Orion.speech.synthSupported     // live getters
Orion.speech.recognition.use(fakeCtor)  Orion.speech.synthesis.use(fakeSynth)   // no argument restores the native engine

<o-tts>

AttributeTypeDescription
textstringFalls back to light-DOM text content when empty.
lang / voicestringForwarded to speak().
rate / pitch / volumenumberAll default 1.

Events: o-start · o-boundary { charIndex } · o-end · o-error { error }. Methods: play() pause() resume() stop().

Keyboard

KeyAction

Accessibility

The mic button has an aria-label/title and aria-pressed reflecting listening state; announce() reports "Listening…" and errors. <o-tts>'s status text is a role="status" region.

Limitations

  • SpeechRecognition has no Firefox support as of this writing; voice lists and onboundary granularity vary by browser/OS/voice — some engines only report sentence boundaries, so <o-tts>'s word highlight may not advance even though playback works.
  • listen() reports failures through onEnd({ error }) rather than the same permission-state taxonomy as camera/recorder — SpeechRecognition does not expose stable DOMException names for "denied" vs. "no microphone".
