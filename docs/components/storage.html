Storage

Namespaced Web Storage with JSON values, expiry and cross-tab change events, a promise-based IndexedDB wrapper with a ready-made key-value store, Cache API helpers, quota and persistence, and <o-storage-inspector> for managing it all during development.

Overview

These helpers never throw because storage is unavailable. When the browser blocks storage (private mode, sandboxed iframes, a full quota), Orion.store falls back to memory and reports persistent: false, and Orion.idb.kv falls back to memory too. Real failures such as constraint violations or quota errors reject with an Orion.StorageError that carries a code of EQUOTA | ECONSTRAINT | EVERSION | EBLOCKED | EUNSUPPORTED | EIDB | ECACHE.

UseFor
Orion.store / Orion.sessionSmall settings, UI state and filters (synchronous, about 5 MB, strings as JSON).
Orion.idbRecords, offline data and files. Large, asynchronous, indexed, and stores Blobs.
Orion.cacheHTTP responses and assets (Cache Storage, shared with service workers). Needs HTTPS or localhost.

Local & session storage

Keys are stored as <namespace>:<key>. The default namespace is orion:store, and Orion.store.namespace('myapp') creates another one. Values go through JSON. Items with a ttl expire on read. onChange(key | '*', fn) fires for changes in this tab (source: 'local') and in other tabs through the storage event (source: 'remote'). Open this page in two tabs to see it.

      Orion.store.set('filters', { status: 'active' }, { ttl: '7d' });   // ttl: ms | '30s' | '10m' | '2h' | '7d'
      Orion.store.get('filters', {});                                     // default when missing or expired
      Orion.store.update('recent', list => [id, ...list].slice(0, 10), []);
      const off = Orion.store.onChange('filters', (value, old, { source }) => table.setFilters(value));
      const app = Orion.store.namespace('acme');  app.keys();  app.clear('draft:');  app.size();

IndexedDB

Orion.idb.open(name, { stores }) creates any missing object stores and indexes. When you don't pass version, it bumps the database version for you when the schema changes. Every method returns a promise. tx(stores, mode, fn) runs several operations in one transaction, commits when fn resolves and rolls back when it throws. Only await IndexedDB requests inside fn, because the transaction closes when it has nothing left to do.

Key-value store

Orion.idb.kv is a ready-made store with no schema, useful for drafts, offline snapshots and larger settings. It uses the orion-kv database and falls back to memory when IndexedDB is unavailable.

Cache management

Orion.cache wraps the Cache Storage API. put() accepts a Response, a Blob, a string or any JSON value, and an optional ttl. match() returns the parsed data, or undefined when the entry is missing or expired. Service-worker caches (orion-sw-*) live in the same storage and show up in the inspector.

Quota & persistence

Browsers may evict best-effort storage under pressure. Orion.storage.persist() asks for persistent storage. Chrome grants it automatically to installed or frequently used sites, and Firefox asks the user. estimate() returns usage and quota for the whole origin.

Storage inspector

<o-storage-inspector> is a development widget. It lists localStorage and sessionStorage keys (size, expiry, value), IndexedDB databases and Cache Storage caches (entries, bytes), and shows the quota. Destructive buttons ask for a second click ("Confirm?") instead of opening a blocking dialog. Use prefix to show only your keys and readonly to hide the delete buttons.
