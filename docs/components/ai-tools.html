AI Everywhere

Small, attribute- and function-driven helpers that drop AI into plain markup: ghost-text autocomplete for any input/textarea, an "improve with AI" rewrite & tone toolbar, one-line summarize / rewrite / translate, form filling from free text, document analysis, and an AI-answer provider for <o-global-search>. All of it calls Orion.ai — configure a provider once and every helper on this page uses it.

Setup

Every demo below runs against the offline mock provider, exactly like your tests would:

Orion.ai.configure({ provider: Orion.ai.mock({ latency: 250, speed: 14 }) });

Ghost-text autocomplete — data-o-ai-complete

Add the attribute to any <input>/<textarea>. Once the caret is at the end of the text and typing pauses, a suggestion appears greyed out after the caret. Tab (or →/End at the end of the field) accepts it into the field; Esc or further typing dismisses it. The attribute's value is a short free-text hint about what is being written.

<textarea data-o-ai-complete="a reply to a customer support ticket"
          data-o-ai-complete-min-chars="8"   <!-- default 8 -->
          data-o-ai-complete-delay="450"     <!-- default 450ms debounce -->
          data-o-ai-complete-max="160"></textarea>   <!-- default 160 — max suggestion length -->

Improve with AI — data-o-ai-suggest

A small ✦ button appears at the top corner of the field while it has focus and text. Click it for tone/rewrite presets (or a custom instruction / target language), then review a word-diff of the AI's rewrite before Accept, Retry or Discard. It operates on the field's whole value; for selection-aware rewriting inside a page use <o-assistant>'s "Replace selection" instead.

<textarea data-o-ai-suggest></textarea>

Summarize, rewrite, translate

Orion.ai.summarize(text | element, opts), .rewrite(text | element, { instruction }) and .translate(text | element, { to }) accept a plain string, a selection's text, or any element (its .value or .textContent) and return Promise<string>.

Fill a form from free text — Orion.ai.fillForm()

Orion.ai.fillForm(form, text, opts) reads the form's named fields (Orion.formFields), asks the AI to pull matching values out of the text, and shows a panel listing each proposed value — old value struck through, new one next to it, all checked by default. The form is only written to when you click Apply (Orion.fill); Cancel discards the proposal untouched.

Document analysis — Orion.ai.analyze()

Orion.ai.analyze(file | text, opts) → Promise<{ summary, keyPoints, entities, fields, raw }>. file may be a plain-text File/Blob (.txt/.md/.csv/.json/…) — a zero-dependency build cannot parse PDFs, so a .pdf rejects with a message pointing at a dedicated parser instead of failing silently.

AI search — Orion.ai.searchProvider()

Orion.ai.searchProvider(opts) returns a provider you drop into <o-global-search>'s providers array (see its docs for the full provider/result contract) — it adds an "AI answer" category that answers the typed query directly.

searchEl.providers = [
  Orion.ai.searchProvider({ minChars: 4 }),   // { id='ai', title, icon='sparkles', minChars=4, system, provider, sources }
  ...otherProviders,
];

Notes & limitations

  • All of it is built on Orion.ai — configure a provider before using any helper on this page (the ai package is a hard dependency, declared via @deps).
  • Ghost text and "improve with AI" operate on the field's whole value, not a partial selection.
  • fillForm() skips password/file/hidden fields and de-dupes radio/checkbox groups to their first control; it asks for one value per field name, so multi-value checkbox groups are not extracted as arrays.
  • analyze() cannot parse PDFs in a zero-dependency build — convert to text/Markdown first, or pair it with a dedicated PDF/OCR extractor and pass the extracted text in.
