Dashboard

<o-dashboard> and <o-widget> build a customizable analytics grid: drag widgets by their header, resize from any edge or corner, add more from a searchable catalog, and persist the whole layout to localStorage — all with plain CSS grid underneath (RTL mirrors for free) and full keyboard support.

Overview

Turn on Edit layout, then drag a widget by its header, resize it from the bottom-right corner, collapse the revenue chart, or open the catalog to add a widget. Reload the page — the layout, added widgets and collapsed state are all remembered (persist="demo-analytics"). Reset clears that and restores the original layout.

Widget chrome

Every widget can offer refreshable (fires o-widget-refresh; call detail.waitUntil(promise) to show a spinner), fullscreen, collapsible, settings (fires o-widget-settings — wire up your own panel) and removable from its header menu. Content renders lazily the first time a widget scrolls into view (lazy, on by default) and is a real DOM subtree — moved in, not cloned or re-rendered — so framework-mounted content survives.

JS API & events

Grid math: Orion.gridLayout

The collision/compaction/breakpoint math that powers <o-dashboard> is exposed as plain functions over layout-item arrays ({ id, x, y, w, h, minW, minH, maxW, maxH, locked }), reusable outside the component — for example to validate a layout on the server before saving it. Every function mutates the items it is given; pass a clone if you need to keep the original.

Keyboard

KeyAction
TabFocus the next widget (in edit mode) or its controls.
Arrow keysA focused widget: move it by one column/row (respects RTL).
Shift + Arrow keysResize the focused widget by one column/row.
Delete / BackspaceRemove the focused widget (with confirmation, unless confirm-remove="false").
EscapeCancel an in-progress keyboard or pointer move/resize; exit a maximized widget.
↓ / ↑ on the menu buttonOpen the widget's action menu.

Every move/resize/collapse is announced to screen readers, and the whole grid, each widget (role="region", labelled by its heading) and the action menu (role="menu") carry correct ARIA.

Orion.dashboard() & declarative actions

Orion.dashboard(el, options) creates (or configures) an <o-dashboard> from any props plus on: { 'layout-change': fn }. <button data-o-action="dashboard" data-o-value="edit|catalog|reset|save|compact" data-o-target="#dash"> wires the toolbar buttons above with no JS.

Orion.gridLayout

Pure functions over plain layout-item arrays — the same math <o-dashboard> is built on (see the demo above). Every function mutates the items it is given; call Orion.gridLayout.clone(list) first if you need to keep the original.

FunctionDescription
clone(list)Shallow-per-item copy so callers can mutate safely.
collides(a, b)true when two items overlap (also false for the same id).
compact(list, mode, pinId?)Resolve overlaps; mode: 'vertical' floats every unlocked item up. pinId anchors one more item in place for this pass (used right after a drag/resize).
move(list, id, x, y, mode, cols)Move an item — colliding neighbours first try to swap above it, otherwise are pushed down — then compact.
resize(list, id, w, h, mode, cols)Resize an item (clamped to its min/max), pushing colliding items down, then compact.
freeSpot(list, w, h, cols)First free { x, y } for a w×h item (top-to-bottom, inline-start to inline-end).
derive(src, srcCols, cols, mode?)Scale a layout designed for srcCols columns to cols columns — used for breakpoints that have no explicit layouts[bp] override.
valid(list, cols)true when no two items overlap and all are inside [0, cols).
bottom(list)Highest occupied row + 1.
