Offline

Orion.offline tracks connectivity (real and simulated), queues mutating requests made while offline, and replays them in order once you're back — persisted in IndexedDB (falling back to localStorage, then memory) so the queue survives a reload. <o-offline-banner> shows the state automatically.

Simulate offline

Orion.offline.simulate(true|false|null) overrides the real network state — handy for demos and tests. Toggling it below drives every demo on this page and the banner underneath.

Request queue & replay

Pass offline: 'queue' to a mutating Orion.http call: while offline it resolves immediately with { queued: true, id } instead of failing, and the request is stored for replay, in order, as soon as the connection returns (or call Orion.offline.sync() yourself).

<o-offline-banner>

Appears automatically while offline, shows the number of queued changes with a Retry button, then a transient "Back online" / "Syncing…" message. Use state to force a state for previews.

Service worker queueing

The offline queue above runs in the page. A service worker route with queue: true queues failed mutations at the network level instead (survives the page closing) and replays them on activation, Background Sync, or the next successful request — see caching strategies.
