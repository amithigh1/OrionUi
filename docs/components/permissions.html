Permissions

Orion.auth holds the current user's roles and permissions; data-o-permission / data-o-role hide, disable, blur or remove elements the user can't use, and <o-can> does the same declaratively with a fallback slot. Re-evaluated automatically whenever the user changes.

UI checks are cosmetic — always enforce permissions on the server too.

Role switcher

Switching roles calls Orion.auth.setUser({ roles, permissions }), which re-evaluates every element on the page. Try each role against the panel below.

Denied modes

data-o-deniedEffect
hide (default)Adds .o-perm-hidden (display: none).
disableNative controls get disabled; other elements get aria-disabled="true", lose href/tabbing, and swallow clicks — with a tooltip explaining why.
readonlyForm fields inside become read-only (or disabled where read-only isn't supported); the element gets aria-readonly.
removeDetached from the DOM entirely (replaced by a comment placeholder) and reinserted if access is granted again.
blurMade inert and visually blurred (.o-perm-blur) with a screen-reader-only explanation.

API

MemberDescription
Orion.auth.setUser({ id, name, roles, permissions })Sets the current user (null to sign out). Permissions accept wildcards ('posts.*', '*.view', '*') and explicit denies ('-posts.delete' or '!posts.delete').
Orion.auth.defineRoles({ role: [...] | { permissions, inherits } })Registers roles; inherits pulls in another role's permissions.
Orion.can(permission, { any, user }) → booleanAccepts one, an array, or a 'a, b' string; any: true = OR instead of AND.
Orion.hasRole(role, { all, user }) → booleanAny by default (OR); all: true requires every role. Inherited roles count.
Orion.auth.guard(permission, onDenied?, { any, role }) → booleanLike can() but shows a toast/announcement (or calls onDenied) when denied.
Orion.auth.protect(permission, fn, onDenied?, opts) → fnWraps a function so it only runs when allowed.
Orion.auth.user / .isAuthenticated / .roles / .permissionsRead-only getters (roles/permissions are the effective, expanded sets).
Orion.auth.update(patch) / .clear() / .refresh() / .onChange(fn)Patch the current user, sign out, force re-evaluation, or subscribe.

Attributes

AttributeDescription
data-o-permission="a.b, c.d"Requires every listed permission (add data-o-permission-any for OR).
data-o-role="admin, manager"Requires any listed role.
data-o-denied="hide|disable|readonly|remove|blur"How to react when denied (default hide).
data-o-denied-message="…"Custom tooltip/description text.
data-o-accessSet automatically to granted or denied (useful for CSS/testing hooks).
