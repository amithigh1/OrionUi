Dynamic forms

Three packages that compose: <o-form> renders a whole form from a JSON schema, data-o-show-if/hide-if/enable-if/require-if make any part of a form conditional on another field's value, and <o-repeater> repeats a group of fields (line items, work experience…). All three integrate automatically with Orion.validate.

<o-form> from a JSON schema — profile form

Pass a schema object as the schema property (or JSON in the schema attribute). A computed field recalculates on every change.

Field types gallery

Every built-in type renders a native control unless a matching Orion custom element (<o-select>, <o-rating>, <o-tags>…) is registered, in which case it's used automatically. Set native: true on a field to force the native control.

Sections & async, dependent options

Group fields with layout.sections; a field's options can be an async function, re-run whenever the fields named in dependsOn change.

Skip logic: showIf / hideIf / enableIf / requiredIf — conditional billing address

Inside <o-form>, conditions can be a string, an object, or a function (see the table below for operators). The same engine is available directly as data-o-show-if on any element.

The same engine used declaratively, outside <o-form>. Field names resolve against the closest <form> or [data-o-scope] ancestor (falling back to the whole page), so wrap standalone usage in one of those to keep it isolated from same-named fields elsewhere on the page.

<o-repeater> — repeatable work-experience rows

Each control's name inside the <template> is re-indexed automatically: company → experience[0][company].

Orion.form.registerField(type, def)

Register a custom field type before creating the form. This one renders a range slider with a live output.
