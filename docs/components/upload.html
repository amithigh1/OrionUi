Upload

<o-upload> is a zero-dependency, form-associated file uploader: drag & drop, clipboard paste, folder drops, MIME/extension/magic-number validation, image & video previews, chunked and resumable transport, and six ready-made layouts. This page covers the everyday features — see Advanced for chunking, resuming, custom transports and the headless Orion.upload() API.

Basic usage

With no url or uploader, the element just collects File objects (nothing is sent anywhere) — useful inside a plain <form>. Give it a transport to start uploading: this demo uses Orion.upload.mock(), a fully in-memory server emulator built for these docs (and for your own offline tests) that simulates latency, throughput and random failures.

Drag & drop

The default dropzone variant accepts a click, a drop, or a paste from the clipboard (paste="element" is the default — focus or hover the zone and press Ctrl/Cmd+V). Dragging a folder over the zone walks it recursively with webkitGetAsEntry and keeps relative paths.

Multiple files & manual upload

Set multiple and, optionally, parallel to cap how many files upload at once. Without auto, files sit as queued until upload() is called (here, by the summary bar's Upload button) — handy for a "review, then submit" flow. Try pausing, canceling and retrying a file (a failed upload from the 15% simulated failure rate above shows a Retry action).

Validation & rejected files

Files are checked before upload: accept matches MIME type, extension or a image/* wildcard, and is cross-checked against the file's real content (magic-number sniffing) so a renamed .exe can't pass as a .png. max-size / min-size / total-max-size / max-files and image min-width / max-width / min-height / max-height add more rules, and a custom validate(file) function can reject or approve anything else. Rejected files are never added to the queue but are announced and shown as an error line; listen for o-reject to build your own list.

Try dropping a .txt file, a large image, a tiny (< 200px) image, or renaming a text file to .png — the content sniffing catches the mismatch.

Previews

Images get a downscaled, EXIF-orientation-corrected thumbnail (drawn on a canvas, so a sideways phone photo previews upright); videos get a poster frame grabbed from their first second; everything else gets a type icon with the extension. Previews are generated off the main thread's critical path and revoked automatically when a file is removed.

Variants

One element, six layouts: dropzone (default, large drop target), button (inline trigger), compact (single-line control that fits a form grid), avatar (round photo picker), gallery (thumbnail grid, drag to reorder with sortable) and inline (slim card, same drop/paste/validate behavior as dropzone).

All variants but avatar respect multiple; avatar and single-file compact always keep the latest file only. Drag two images into the gallery above, then drag a card to reorder — the order is exposed through getFiles() and the o-sort event.

Inside a <form>

<o-upload> is form-associated: give it a name and it participates in the form's FormData, validity (required works) and reset() like any native input — no uploader/url needed. When a transport is configured, set submit="files" to always send the raw Files on native submit regardless of upload state, or submit="response" to send the server's id(s) once uploaded (the default, auto, picks response when a transport exists and files otherwise).

Events

EventDetailDescription
o-add{ file, item, id }A file passed validation and was queued.
o-reject{ file, item, id, reason, message }A file failed validation. reason: type, mismatch, maxSize, minSize, totalSize, maxFiles, duplicate, minWidth/maxWidth/minHeight/maxHeight, crop, custom.
o-remove{ file, item, id }A file was removed from the list.
o-start{ file, item, id }A file began uploading.
o-progress{ file, item, id, loaded, total, percent, speed, eta }speed in bytes/s, eta in seconds (both smoothed; null until enough samples exist).
o-success{ file, item, id, response }A file finished uploading.
o-error{ file, item, id, error, message }A file failed after exhausting retries.
o-complete{ files, failed }The whole batch settled (no more active/queued/paused files).
o-pause / o-resume / o-cancel / o-retry{ file, item, id }Mirrors the matching method call, from the UI or from code.
o-resumed{ file, item, id, offset }A chunked/tus upload resumed from a non-zero byte offset.
o-sort{ files }The list was reordered (drag or keyboard).
o-preview{ file, item }Cancelable; fired before preview() opens a file (call preventDefault() to supply your own viewer).
o-before-remove{ file, item }Cancelable; fired before a file is removed.
o-change{ files, value }The public value changed (add/remove/upload-complete in submit="response" mode); also native input + change.
