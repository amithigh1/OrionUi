HTTP & AJAX

Orion.http is a small fetch-based client with typed errors, retries with backoff and jitter, timeouts, cancellation, interceptors, request de-duplication, caching, CSRF, upload and download progress, plus attribute behaviors for AJAX forms and HTML fragments.

Overview

Every call resolves with the parsed body (JSON, text or Blob, chosen from Content-Type) or rejects with an Orion.HttpError. Plain objects are sent as JSON. FormData, Blob and URLSearchParams bodies are sent as they are. The demos on this page read JSON fixtures from docs/fixtures/services-a/. Writes, latency and errors come from Orion.http.mock, so no backend is needed.

      const users = await Orion.http.get('/api/users', { params: { role: 'Admin' }, timeout: 8000, retry: 2 });
      const saved = await Orion.http.post('/api/users', { name: 'Ada' });          // JSON body + X-CSRF-Token from <meta name="csrf-token">
      try { await Orion.http.delete('/api/users/7'); }
      catch (e) { if (e instanceof Orion.HttpError && e.status === 409) alert(e.userMessage); }

Requests

Retries, timeouts & cancellation

retry takes a count or { count, delay, factor, maxDelay, jitter, on, methods, network, when }. Retries apply to idempotent methods (GET, HEAD, OPTIONS, PUT, DELETE) on 408, 425, 429 and 5xx responses and on network errors. A Retry-After header overrides the backoff. The timeout applies to each attempt. Aborting through a signal never retries.

Instances & interceptors

Orion.http.create(defaults) returns an independent client (own interceptors, cache and events) that inherits the defaults you pass. Interceptors run in order. use(fn) returns an eject() function. A request interceptor may change the config or return a new one. A response interceptor receives { data, status, headers, config, response, cached }. An error interceptor that returns a value resolves the request, which is useful for refreshing a token.

De-duplication & caching

Identical GET requests that are in flight at the same time share one network request (dedupe: true by default). Each caller gets its own copy of the data and can still abort on its own. cache: 'memory' keeps the result for the page session and cache: ms keeps it for a time-to-live. POST, PUT, PATCH and DELETE requests clear cached entries for the same resource path.

Upload & download progress

When you pass onUploadProgress, the request goes through XMLHttpRequest because fetch has no upload progress. onDownloadProgress reads the response stream. Both callbacks receive { loaded, total, progress (0..1 or null), lengthComputable }. Orion.http.upload() wraps files in FormData. Orion.http.download() saves the file using the Content-Disposition filename and shows a progress toast when the toast package is loaded.

AJAX forms

Add data-o-ajax to a <form> to submit it through Orion.http. The form is sent as JSON, or as FormData when it contains files. While the request runs, the submit buttons are disabled and show is-loading. A 422 response with { errors: { field: message } } (Laravel, Rails, ASP.NET ProblemDetails and express-validator formats are all supported) marks the matching .o-field as invalid. The error clears as the user types. Try the email ada@taken.com.

Other attributes: data-o-ajax="json|formdata" forces the encoding, and data-o-ajax-reset, data-o-ajax-redirect="/url", data-o-ajax-target="#el" (HTML responses), data-o-ajax-offline (queue while offline), data-o-ajax-retry="2", data-o-ajax-timeout="10000" and data-o-ajax-loader are also supported. Cancel o-ajax-before to stop a submit or edit detail.config. Cancel o-ajax-error when a forms package renders errors itself.

HTML fragments

data-o-load="url" fetches HTML into its element, or into data-o-target. The fragment is sanitized unless you add data-o-trusted. Empty containers show a skeleton while they load. Triggers are load, click (the default for buttons), visible, every 30s or any DOM event, and you can combine them, for example load, every 5s. The activity fixture below contains a <script> and an onclick, and both are removed. The news list is first-party markup with inline SVG icons, so it uses data-o-trusted. Scripts in fragments never run, even when trusted.

      await Orion.http.load('#panel', '/fragments/orders.html', { select: '.o-card', swap: 'inner', trusted: false });

Mock server (testing)

Orion.http.mock(routes, { delay, passthrough }) answers matching requests in memory for every client instance, so demos, prototypes and tests can run without a backend. Unmatched requests go to the network. A route can simulate latency (delay: 300 or [min, max]), a status, flaky behaviour (fail: 2), error: 'network' | 'timeout' and upload or download progress. Handlers receive { method, url, path, query, params, headers, body, attempt }.

      const server = Orion.http.mock([
        { method: 'GET',  url: '/api/users/:id', response: req => ({ id: +req.params.id }) },
        { method: 'POST', url: '/api/users', status: 201, delay: [200, 600], response: req => ({ id: 7, ...req.body }) },
        { method: 'POST', url: '/api/profile', reply: req => [422, { errors: { email: 'Taken' } }] },   // [status, body, headers]
        { url: '/api/flaky', fail: 2, status: 503, response: { ok: true } },                        // 2 failures, then 200
        { url: '/api/down', error: 'network' },
      ], { delay: 150 });
      server.calls;      // [{ method, url, path, body, headers, time }]
      server.reset();    // clear calls and fail counters
      server.restore();  // remove the routes

Accessibility & frameworks

Busy forms and containers get aria-busy. Field errors are linked with aria-describedby and aria-invalid, the first invalid field receives focus, and results are announced through a live region. In React, Vue or Angular, call Orion.http from effects or services and pass an AbortController signal so requests are cancelled on unmount. The client loads in Node (SSR) without touching window.
