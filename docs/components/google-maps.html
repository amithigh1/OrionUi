Google Maps Integration

The built-in <o-map> needs no external service. If you would rather render an actual Google Map (satellite/street imagery, Google's own geocoding, Street View), set provider="google" and supply your own API key — <o-map> keeps its element API (setView, markers, popups, fitBounds, o-* events), just backed by the real Google Maps JavaScript API instead of the built-in slippy map.

The Google Maps JS API script is only ever requested when you call Orion.maps.google.load({ key }) or set api-key on a provider="google" element — never on page load, and never with a key baked into Orion. This documentation page ships no key and makes no request to Google; the demo below only runs if you paste in your own.

Getting a key

Create a project in the Google Cloud Console, enable the Maps JavaScript API (and Places API if you also want <o-address-input provider="google">), enable billing, and restrict the key to your domain(s). Google Maps is a paid, metered service beyond a monthly credit — review their pricing before going live.

<o-map provider="google">

Add provider="google" and api-key. Everything else — lat/lng/zoom, markers, addMarker/updateMarker/removeMarker, popups (via Google's InfoWindow), o-click/o-move/o-zoom/o-marker-click/o-marker-drag-end — works the same as the built-in map, so a component built against <o-map> does not need to know which provider is active. map-id enables Google's newer Advanced Markers and cloud-based styling.

      <o-map
        provider="google"
        api-key="YOUR_KEY"
        lat="1.2840" lng="103.8512" zoom="14"
        markers='[{"id":"hq","lat":1.2840,
                   "lng":103.8512,"title":"HQ"}]'>
      </o-map>

The script loads once (cached) the first time a provider="google" element connects, or earlier if you call Orion.maps.google.load() yourself (recommended — it lets you show your own loading state and catch the promise's rejection).

Orion.maps.google (loader service)

Load the API yourself — for example to also use google.maps.places for <o-address-input provider="google">, before mounting any map:

      await Orion.maps.google.load({
        key: 'YOUR_KEY',
        libraries: ['places', 'marker'],
      });
      // Orion.maps.google.loaded is now true — every
      // <o-map provider="google"> (and address input)
      // on the page can render synchronously from here on.

Address search with Google Places

After loading the places library, <o-address-input provider="google"> (see Address Autocomplete) uses AutocompleteService for suggestions and PlacesService to resolve the picked prediction into a full address.

      <script>
        await Orion.maps.google.load({
          key: 'YOUR_KEY', libraries: ['places'],
        });
      </script>
      <o-address-input provider="google">
      </o-address-input>

Notes & limitations

  • Vector layers (addLayer/addGeoJSON) and the marker-list accessibility view are specific to the built-in provider and are not (yet) mirrored onto the Google adapter — use Google's own Polyline/Polygon/Data APIs via map._g (the underlying google.maps.Map instance) if you need them with provider="google".
  • scroll-zoom, tiles, tile-filter and clustering are specific to the built-in renderer and have no effect with provider="google" (Google's own gesture handling and marker rendering apply instead).
  • Switching provider back and forth on a live element is supported but not recommended — prefer choosing one provider per element.
