Gantt chart

<o-gantt> plans projects: an editable task tree on the left and a virtualized timeline on the right, with dependencies of all four types, drag-and-drop scheduling, auto-scheduling, the critical path, baselines, working-day calendars, undo/redo and PNG, PDF and JSON export. It renders thousands of tasks smoothly and works with a keyboard, a screen reader, a touch screen, in dark mode and right to left.

Software project

A product launch split into phases, tasks and milestones. The plan is computed with Orion.gantt.schedule() from durations and dependencies, the critical path is highlighted in red, and the company offsite is a holiday. Drag a bar to move it, drag its edges to change its length, drag the small triangle to set progress and drag from a bar's dot to another bar to link them. Moving a task pushes its successors.

Views & zoom

Five presets set the time scale: day, week, month, quarter and year. The header adapts its two tiers (for example month over days, or year over quarters) and labels are formatted with the current locale. Hold Ctrl and scroll (or pinch on a trackpad) to zoom continuously around the pointer, use the toolbar, or call zoomIn(), zoomOut(), setView(). Weekends and holidays are shaded when days are wide enough to see.

Dependencies & auto-scheduling

Each task lists its predecessors in dependencies: plain ids (finish-to-start) or { id, type, lag } objects with 'FS', 'SS', 'FF' or 'SF' and a lag in working days (negative for a lead). With auto-schedule (on by default), a change pushes every dependent task later so that each dependency still holds; links that would create a loop are refused. Arrows are routed orthogonally and a link to a summary applies to every task inside it.

Scheduling engine

The same engine is available without any UI, for example to compute dates on a server-rendered page or to validate an import:

      const tasks = Orion.gantt.schedule(list, { workingDays: [1, 2, 3, 4, 5], holidays: ['2026-12-25'] });
      const { tasks: critical, slack, finish } = Orion.gantt.criticalPath(tasks);
      const loop = Orion.gantt.findCycle(tasks);      // ['a', 'b'] or null
      const cal = Orion.gantt.calendar({ workingDays: [0, 1, 2, 3, 4] });

Editing, undo & events

Double-click a cell (or press Enter) to edit names, dates, durations, progress and assignees in place. Every edit — dragging, typing, keyboard moves, indenting, adding or deleting — is one step in the built-in undo history (Ctrl+Z / Ctrl+Y). o-task-change is cancelable: this demo refuses to move a task so that it starts in the past. Use detail.revert() later, for example when your server rejects the change.

Working days, holidays & baselines

Durations and lags count working days. working-days lists the weekdays that are worked (0 = Sunday … 6 = Saturday; default Monday–Friday) and holidays adds days off, as 'YYYY-MM-DD' strings or { date, name } objects. Moving a task skips non-working days and keeps its working duration. baselineStart/baselineEnd draw the original plan under each bar; the tooltip shows the variance.

Columns

columns chooses and orders the task-list columns: built-in keys (name, start, end, duration, progress, assignee) or objects with key, label, width, align, editable, type, value(task), render(task) and set(task, value). Extra fields on a task (like status below) are kept and returned by getTasks(). Drag a header edge to resize a column and drag the divider to resize the list; on phones the list narrows and the toolbar button hides it.

Read-only roadmap

readonly removes every editing affordance (handles, dots, editors and toolbar actions) but keeps selection, tooltips, zoom and export. This quarterly roadmap uses the quarter view, collapsed groups and a custom tooltip.

2,000 tasks

Rows and the time axis are virtualized: only what is on screen (plus a margin) exists in the DOM, so large plans scroll, zoom and edit without lag. Dependencies, roll-ups and the critical path are recomputed after each edit in a few milliseconds.

Export

The toolbar's Export menu, or the methods: exportPNG(options) draws the chart (and task-list columns) on a canvas and downloads a PNG; exportPDF(options) uses the Orion PDF module when it is loaded and otherwise opens the print dialog so the chart can be saved as PDF; exportJSON() downloads getTasks(). toCanvas(options) returns the canvas for your own use.

      const blob = await gantt.exportPNG({ scale: 2, range: 'all', columns: ['name', 'start'], download: false });
      await gantt.exportPDF({ filename: 'roadmap', orientation: 'landscape' });
      const json = gantt.exportJSON({ download: false });

Frameworks

Set tasks as a property (React 19, Vue :tasks, Angular [tasks]) and listen to o-change or o-task-change to write edits back to your store; getTasks() returns plain JSON-safe objects. Assigning a new tasks array reloads the plan and clears the undo history, so keep the component as the source of truth while the user edits, or apply your own changes with updateTask() to keep history.

      <!-- Vue -->
      <o-gantt :tasks="tasks" view="week" critical-path @o-change="tasks = $event.target.getTasks()" />
      <!-- Angular -->
      <o-gantt [tasks]="tasks" (o-task-change)="save($event.detail)"></o-gantt>
