Presence & Activity

Orion.presence is a tiny shared status store; <o-presence> shows one dot + label, <o-presence-list> a grouped roster. <o-activity-feed> renders an "actor did something" timeline with day grouping, filtering and infinite loading. Statuses (online | away | busy | dnd | offline) match <o-avatar status> exactly.

<o-presence>

Drive it by hand with status/label, or point it at a user id (user-id) to track Orion.presence live.

Orion.presence: set() / subscribe()

Feed the store from your realtime layer; every <o-presence user-id> tracking that id updates automatically. Idle auto-away (autoAway()) needs Orion.idle — see the note below.

<o-presence-list>

group-by="status" (default) buckets by presence priority; "group" buckets by each item's own group field (e.g. a team); "none" is a flat, presence-sorted list. Rows with a live Orion.presence entry override their own status field.

<o-activity-feed>

Each item is { id, actor: { name, avatar? }, verb, target?: { label }, type?, icon?, color?, createdAt } — rendered as actor avatar (<o-avatar name>) · "actor verb target" · a colored icon · relative time. compact tightens it for a dashboard card (this is exactly what templates/dashboard.html uses).

Day grouping & type filter

Without compact, day dividers are easier to see. The filter chip row shows automatically once more than one type is present (or force it with show-filter); pass explicit filters for custom labels.

Paged / infinite loading

source(page, {pageSize}) returns a page (or {items, hasMore}); load() pulls one page, auto-load pulls automatically as the sentinel scrolls into view.

Keyboard & a11y

<o-presence> is role="status" (announces changes without moving focus). <o-presence-list> and <o-activity-feed> rows are tabindex="0" and activate with Enter / Space. Status/type is never color-only — every indicator carries text.
