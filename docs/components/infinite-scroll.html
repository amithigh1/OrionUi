Infinite Scroll

Orion.infiniteScroll(container, options) loads more data as the user nears the edge of a list — an invisible sentinel and IntersectionObserver do the watching, so there is nothing to wire up on scroll events. Loading, error-with-retry and end-of-list states are built in; a declarative data-o-infinite attribute covers the fetch-and-append-HTML case with no JS at all.

Overview

Give it a load(page, { signal }) function that resolves an array (or { items, hasMore }), and a render(item). New pages load automatically as the sentinel at the bottom nears the viewport.

"Load more" button mode

Set mode: 'button' to require an explicit click instead of auto-loading on scroll — useful for expensive pages, or to keep the user's scroll position predictable.

Errors, retry & latency

A rejected load() shows an error row with a Retry button (this demo fails roughly one page in three). Reaching the end of the data shows an end-of-list row.

Chat-style history (direction: 'up')

Set direction: 'up' to load older items when the user scrolls toward the top, prepending them while keeping the current view perfectly still — the standard pattern for a message thread. The view opens already scrolled to the newest message.

Driving a <o-virtual-list>

When container is an <o-virtual-list>, infiniteScroll hooks its o-near-end / o-near-start events instead of a sentinel, and merges results with appendItems() / prependItems() — no extra DOM to manage, and it scales to very large feeds.

Declarative: data-o-infinite

For a server-rendered feed, skip the JS entirely: point data-o-infinite-url at an endpoint that returns the next page as an HTML fragment ({page} is substituted, or appended as a query parameter). The response is sanitized before insertion unless the element carries data-o-trusted.
