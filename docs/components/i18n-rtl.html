Languages & RTL

Every component string is translatable, numbers, dates and currencies follow the locale, and all layouts mirror automatically for right-to-left languages such as Arabic, Hebrew, Persian and Urdu.

Switching language

Setting a right-to-left language sets <html dir="rtl"> automatically (disable with autoDir: false). Components re-render their strings on the locale event.

Adding translations

      Orion.i18n.add('ms', {
        common: { save: 'Simpan', cancel: 'Batal', items: { other: '{count} item' } },
        table: { search: 'Cari…' }
      }, 'Bahasa Melayu');                       // optional display name

      Orion.i18n.set('ms');                       // switch (persisted)
      Orion.t('common.items', { count: 5 });      // "5 item"
      Orion.i18n.locales();                       // [{ code: 'en', name: 'English' }, ...]

Keys are namespaced per component (select.noResults, table.rowsPerPage…). Plurals use { zero, one, two, few, many, other } objects resolved with Intl.PluralRules. Missing keys fall back to English. Individual components also accept a texts property to override strings per instance.

Right-to-left

Orion uses CSS logical properties (margin-inline-start, inset-inline-end…) everywhere, so layouts mirror with no extra CSS. Directional icons (chevrons, arrows) flip, keyboard arrows follow the reading direction, and floating panels and drawers open from the correct side. Utilities use s/e (start/end) instead of left/right: .o-ms-2, .o-pe-4, .o-text-end.

Locale formatting

See Orion.format. The first day of the week, 12/24-hour clocks, month names and number separators all come from Intl for the current locale. Override them with OrionConfig.weekStart and currency.
