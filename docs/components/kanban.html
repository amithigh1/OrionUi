Kanban

<o-kanban> is a full drag-and-drop task board: columns and swimlanes, WIP limits, quick-add, a compact list variant, custom card templates, filtering and complete keyboard drag & drop. It is built entirely on the Orion.sortable engine from this package.

Overview

Give the board columns and cards (plain data — arrays of objects); the board renders and keeps them in sync as the user drags, adds, edits and deletes. Everything also works as HTML attributes (JSON strings) for server-rendered pages.

      const kb = document.querySelector('o-kanban');
      kb.columns = [{ id: 'todo', title: 'To do', color: 'info', limit: 5 }, { id: 'doing', title: 'In progress', color: 'primary' }];
      kb.cards = [{ id: 1, columnId: 'todo', title: 'Design the empty states', priority: 'high', due: '2026-09-20',
        labels: [{ text: 'Design', color: 'info' }], assignees: [{ name: 'Mei Tan' }], progress: 40 }];
      kb.onMove = async ({ cardId, to, index }) => api.moveCard(cardId, to, index);   // return false / throw to revert
      kb.addEventListener('o-card-move', e => console.log(e.detail));

Project board

A five-column board with labels, assignees, due dates, priority, progress, checklists, cover images, comment/attachment counts and a search + filter toolbar. Design has a WIP limit of 4 and is already over it. Drag a card within or between columns, drag a column header to reorder columns, or focus a card and press Space for keyboard drag & drop. Click a card to open its detail panel.

Swimlanes

Add swimlanes (and give cards a laneId) to group rows by team, epic or anything else. Columns become a sticky header row shared by every lane; drag cards across lanes and columns freely. Lane rows collapse independently.

WIP limits

Set a column limit to show a count badge (3 / 3) that turns amber at the limit and red over it. With wip-block (or a per-column hardLimit) the board refuses to drop another card in — try dragging a card into In review.

List variant

variant="list" turns the board into a single scrollable column of compact rows — a task list grouped by status, handy on narrow screens or as a dense "my work" view. Columns still reorder and cards still drag between them.

Custom card template

Set renderCard(card, kanban) to fully control card markup — return an HTML string, an Orion.util.html template, or a DOM node. The board still adds the card menu button, drag handling and keyboard support around it.

Keyboard drag & drop

Cards and column headers are focusable. The same engine as drag & drop powers keyboard moves, with kanban-specific announcements ("Moved Ship v2 to Doing, position 2").

KeyAction
↑ / ↓Move focus between cards in a column (or the next/previous lane's column in swimlane mode).
← / →Move focus to the nearest card in the column on that side (mirrored in RTL). Not used in the list variant.
SpacePick up the focused card or column header; press again to drop it in place.
Arrow keys (while picked up)Move the card within the list, or to the nearest connected column/lane past the ends.
EscapeCancel the pick-up and return to the original position.
EnterOpen the focused card's detail panel.
Shift+F10 / ContextMenuOpen the card's menu.
F2 / double-click titleRename the focused column.
Home / EndJump to the first / last card in the column.

Methods

Every mutation is also a plain method, so you can drive the board from your own UI (forms, an import wizard, realtime updates). Each one emits the matching cancelable event first.

Programmatic factory — Orion.kanban()

Orion.kanban(target, options) creates an <o-kanban> inside target (a selector or element) and assigns options as properties, returning the element — an alternative to writing the tag and assigning properties yourself.

      const kb = Orion.kanban('#host', { columns: [...], cards: [...], onMove: async (d) => api.moveCard(d) });
      // If #host isn't already an <o-kanban>, it is REPLACED by a new one (not appended inside) — style/size the returned element.

API

Props / attributes

PropTypeDescription
columnsArray{ id, title, color, limit, hardLimit, collapsed, done }. color is a semantic token (primary…) or any CSS color.
cardsArray{ id, columnId, laneId, title, description, labels[], assignees[], due, priority, progress, checklist:{done,total}, comments, attachments, cover }.
swimlanesArray{ id, title, collapsed }. Presence (outside variant="list") switches the board into swimlane layout.
variantString'board' (default) or 'list' — a single compact column of rows.
renderCardFunction(card, kanban) => string | SafeHTML | Node — full control of card markup.
onMoveFunctionasync ({ cardId, from, to, index, ... }) => boolean. Returning/throwing false reverts the move.
wipBlockBooleanRefuse drops (and disable "Add card") once a column's limit is reached. A column's own hardLimit: true does the same regardless of this flag.
filterableBooleanShows the search + assignee/label filter toolbar.
readonlyBooleanDisables dragging, add/edit/delete UI; the board is still browsable and openCard still works.
lockColumnsBooleanCards still drag; columns cannot be reordered, added, renamed or deleted.
addPositionString'top' | 'bottom' (default) — where the column menu's "Add card" inserts.
detailString'panel' (default, built-in side panel) or 'none' (only fire o-card-open; you supply the UI).
persistStringRemembers column order, collapsed state and card order/position in localStorage under this key.
cardActionsArrayExtra { id, label, icon } items appended to the card menu; picking one fires o-card-action.
textsObjectPer-instance text overrides (see this.t() in ARCHITECTURE.md).

Methods

MethodDescription
addCard(data, { position, after, before, user })Insert a card; returns the card or false if vetoed.
updateCard(id, patch, { user })Merge fields into a card (title, labels, due, columnId…).
removeCard(id, { user, quiet })Delete a card.
moveCard(id, columnId, index?, laneId?, { user })Move/reorder a card programmatically (same flow as a drag, including onMove).
addColumn(data, index?, { user })Insert a column.
updateColumn(id, patch, { user })Merge fields into a column (title, color, limit…).
removeColumn(id, { user })Delete a column and its cards.
moveColumn(id, toIndex, { user })Reorder a column.
collapseColumn(id, collapsed?, { user })Collapse/expand (omit collapsed to toggle).
openCard(id) / closeCard() / focusCard(id)Open/close the detail panel; move roving focus to a card.
filter({ text, assignee: [], label: [] }) / clearFilter()Apply or clear the toolbar filter from code.
getData(){ columns, cards, swimlanes } deep-cloned snapshot.

Events

EventDetail
o-card-move (cancelable){ cardId, card, from, to, fromLane, toLane, oldIndex, index, keyboard }.
o-card-move-revertFired after onMove returned/threw false and the card was moved back.
o-card-add / o-card-update / o-card-remove (cancelable){ card } (and { patch } for update).
o-card-open (cancelable) / o-card-close{ card } / { cardId }. Prevent default to show your own UI instead of the built-in panel.
o-card-menu / o-column-menu (cancelable){ card|column, items, anchor, run(id) } — mutate items or call run() yourself; preventDefault() replaces the built-in menu entirely.
o-card-action{ action, card } — a cardActions entry (or unhandled built-in id) was picked.
o-column-move / o-column-add / o-column-update / o-column-remove / o-column-toggle (cancelable)Same shape as the card events, with column.
o-filter{ filter, visible, total } after the toolbar filter changes.
o-change{ reason, columns, cards } — fired after every mutation (good for one debounced autosave hook).

CSS

Custom properties: --o-kanban-col-w (column width, default 18.5rem), --o-kanban-gap. Structural classes: .o-kanban-board, .o-kanban-col (.is-collapsed, .is-over-limit, .is-blocked), .o-kanban-card ([data-priority], .is-pending), .o-kanban-lane, .o-kanban-cell. Drag visuals reuse .o-sortable-placeholder / .o-dnd-ghost from the drag & drop engine.
